# AGENTS.md — instructions for AI agents

This repo turns a local Figma file into two apps, a Go templ static site (`apps/site`) and a Svelte 5 design-system app (`apps/design-svelte`), through generated, checked layers. Read this file, then the rules in [`.cursor/rules/`](.cursor/rules) and the skill [`.cursor/skills/figma-to-site/SKILL.md`](.cursor/skills/figma-to-site/SKILL.md).

## Golden rules

1. **Never hand-edit a generated file.** Generated files carry a `Generated by …` / `Code generated … DO NOT EDIT` header. Change the source and rerun its generator:

   | Source | Generated output |
   |---|---|
   | `fixtures/tokens/mapping.json` | tokens |
   | `tools/content.ts` + `fixtures/content/source/*.json` | records |
   | `tools/views.ts` | views |
   | `packages/ui/recipes/*.variants.json`, `packages/ui/bricks/*` | primitives |
   | `packages/blocks/defs/*.ts` | blocks |
   | `tools/ui8px/allowed.extra.json` | lint policy |

   Every generator has a `--check` mode, and `bun run check` fails on drift.
2. **No `.fig` in the repo.** Keep it outside (e.g. `/workspace/fig-fixtures/`). `*.fig` is git-ignored and `tools/extract.sh` refuses a path inside the repo. Never `git add -f` one.
3. **8 + 4 grid** ([grid-8-4.mdc](.cursor/rules/grid-8-4.mdc)):
   - 1 step = 4px.
   - Layout scope (blocks, apps, `base.css`) uses even steps only: `0 2 4 6 8 10 12 16 20 24 28` (the codegen 2.0 8px grid narrowed to the Habitus rhythm; see [docs/design-settings.md](docs/design-settings.md)).
   - Control scope (`packages/ui`, icons) may also use `1 3 5 7`.
   - No fractional or arbitrary values.
4. **Tokens-only colors** ([tokens.mdc](.cursor/rules/tokens.mdc)):
   - Packages use only shadcn HSL token utilities (`bg-primary`, `text-muted-foreground`, …). No palette colors, no hex.
   - Colors with no shadcn role become `--brand-*` in the **app** `brand.css` only. `bun run check` greps `packages/` for brand tokens.
   - Layout theme vars that packages need (`--text-display`, `--container-page`) live in `packages/tokens/theme.css`.
5. **Adapter: `@apply` only, no inline styles** ([adapter-no-inline-styles.mdc](.cursor/rules/adapter-no-inline-styles.mdc)):
   - Markup carries only semantic `ui-*` classes (packages) and `ds-*` classes (design-app shell).
   - Utilities live in `@apply` rules in `packages/adapter/src/*.css` or app CSS.
   - Tailwind runs with `source(none)`, so a utility written in markup does not exist.
   - No `style="…"`, no `style:`, and no JS that sets styles.
6. **Blocks and retag** ([blocks-retag.mdc](.cursor/rules/blocks-retag.mdc)):
   - `Block` is the only section/landmark/anchor unit, retagged by meaning (`section|header|footer|nav|main|aside|article`).
   - Never nest a Block in a Block. `Box` is internal layout only.
   - Content-model tags come from their primitives (`List`/`ListItem`, `Table*`, `Image`, `Disclosure`, `Form`…).
   - One `h1` per page. Sections use `aria-labelledby` → Title id.
   - At most 45 blocks.
7. **Contract conformance** ([fixtures-contract.mdc](.cursor/rules/fixtures-contract.mdc)):
   - Content is @ui8kit/contract records validated by `bun run contract` (0 errors, 0 warnings).
   - Every image is a `media` entry.
   - Components never hard-code copy; both runtimes render the same `fixtures/views/*.json`.
8. **Runtime parity:**
   - Templ and Svelte output must give identical normalized DOM: `packages/ui` parity and `packages/blocks` parity report **0 mismatches**.
   - A feature added to one runtime is added to all through the generators, never by hand in one app.
9. **Dark mode** ([dark-mode.mdc](.cursor/rules/dark-mode.mdc)):
   - `.dark` on `<html>` is set by `packages/ui/behaviors/theme-init.js`, the **only** allowed inline script, in `<head>`.
   - Islands are forced with `data-theme="light|dark"`. Never name a plain variant key `light` or `dark` if it ends up in `data-theme`.
   - Pastel tiles get deep dark tones.
   - The `dark:` variant does not see `data-theme` islands.
10. **Sheet and behaviours** ([sheet.mdc](.cursor/rules/sheet.mdc)):
    - Interactive behaviour lives only in `packages/ui/behaviors/ui8kit.js`, wired through `data-ui8kit` hooks, with no framework.
    - The Sheet has `role="dialog"` and `aria-modal`, traps focus, closes on Esc and overlay click, and restores focus.
    - Local bricks live in `packages/ui/bricks/` and are added to the codegen registry in `packages/ui/scripts/registry.ts`.
    - The site burger is shown below `lg` (user decision, 2026-10-18).
11. **Git** ([git-workflow.mdc](.cursor/rules/git-workflow.mdc)):
    - Make small commits and push after each verified step.
    - No force push, no amend or rebase of pushed commits, no changes to `~/.gitconfig`.
    - Follow the author and push command used in that rule when you operate in this environment.

## Pipeline order

Run from the repo root. Each step lists only what to rerun after a change in that layer; later steps depend on earlier ones.

```bash
# 1. extract (only when the .fig changed; FIG must be outside the repo)
FIG=/abs/path/file.fig bun run extract            # → fixtures/figma

# 2. content records + validation, 3. views
bun run content                                   # → fixtures/content/records
bun run contract                                  # errors 0, warnings 0
bun tools/views.ts                                # → fixtures/views/{home,blocks}.json

# 4. tokens (+ brand-os, network)
bun run tokens                                    # → fixtures/tokens/*, packages/tokens/theme.css, app brand.css
bun run brand:emit && bun run brand:check         # brand-os@0.3.0 (not part of `check`)

# 5. primitives, 6. icons, 7. blocks
(cd packages/ui && bun run generate && bun run parity)
(cd packages/ui/templ && go run github.com/a-h/templ/cmd/templ@v0.3.1070 generate -path ui)
(cd packages/icons && bun scripts/generate.ts)
(cd packages/blocks && bun run generate && bun run parity)

# 8. lint policy + lint
bun tools/ui8px-policy.ts && npx -y ui8px@latest lint   # Violations: 0

# 9. apps
bun run site:build                                # apps/site/public
(cd apps/design-shared && bun run generate) && (cd apps/design-svelte && bun run build)

# 10. gate
bun run check                                     # "all checks passed"

# 11. visual verification (Chrome; output outside the repo, /workspace/shots-saas)
bun run render:figma && bun run shots             # Figma vs site, report.json deltas
bun run shots:design && bun run shots:modes       # design pages; light/dark/390px menus
bun run test:behaviors                            # Sheet + ThemeToggle behaviour (18 assertions)
```

Details of each check and how to fix it: [docs/checks.md](docs/checks.md). For a new Figma file: [docs/replicate-with-new-figma.md](docs/replicate-with-new-figma.md). For a new runtime: [docs/add-a-runtime.md](docs/add-a-runtime.md).

## How to interpret common requests

Users often phrase requests the way the [README examples](README.md#use-it-with-an-ai-agent) do. Map them like this, and confirm assumptions in your first reply.

| Request | Interpretation |
|---|---|
| "A restaurant site in this same design, on React, in `apps/resta`" | **New app folder** `apps/resta`, one per request. **Reuse** `packages/tokens`, `packages/adapter`, the behaviours and the fixtures pattern. New content goes in as contract records: extend `tools/content.ts` / `fixtures/content/source`, then `tools/views.ts` view models. Never hard-code copy in components. Primitives: add the `react` runtime to `packages/ui/scripts/generate.ts`. Blocks: write a React block emitter ([docs/add-a-runtime.md](docs/add-a-runtime.md)); none exists yet. Add the app to `tools/check.sh`, the screenshot tools and `tools/test-behaviors.ts`, plus a `vercel.json`. |
| "Study this repo and build a site + design system for this (other) Figma design, on Vue" | Follow [docs/replicate-with-new-figma.md](docs/replicate-with-new-figma.md): extract with `FIG=` outside the repo, remap `fixtures/tokens/mapping.json`, rewrite the design-specific scripts (table in that doc), map frames to blocks, regenerate, then measure drift. Do the runtime part as in [docs/add-a-runtime.md](docs/add-a-runtime.md). Credit the new design's author and check its license (CC BY or other) the same way [LICENSE-DESIGN.md](LICENSE-DESIGN.md) does. |
| "Same design, different content" | Change only the fixtures (`tools/content.ts` mapping, `fixtures/content/source/*.json`, media entries), then run `bun run content && bun run contract && bun tools/views.ts`. Leave blocks and tokens unchanged unless asked. |
| "Add a page" | Site: add a view file (e.g. `fixtures/views/<page>.json`, written by `tools/views.ts`) and an entry in `pages` in `apps/site/cmd/export/main.go`. Design app: add a route. Reuse existing blocks; add a block only when no block fits (≤ 45 total). |
| "Change the brand colors / dark theme" | Edit `fixtures/tokens/mapping.json` only, then `bun run tokens`, then `shots:modes`. |

### Single-runtime mode ("React only", "Vue only", "Svelte only", "templ only")

When the user wants **one** runtime, do not keep the others in parity. Remove them once, in a dedicated commit, so `bun run check` stays meaningful:

| Keep only… | Drop | Adjust |
|---|---|---|
| **Svelte** | `apps/site`; templ output of `packages/ui/templ`, `packages/blocks/templ`, `packages/icons/templ`; the templ emitters in `packages/blocks/scripts/generate.ts` | `tools/check.sh`: remove the `templ generate`/drift lines and the apps/site step. Parity scripts: compare Svelte against the canonical renderer only (ui) or drop the cross-runtime DOM comparison (blocks). Go is no longer a prerequisite. |
| **templ** (static HTML) | `apps/design-svelte`; `packages/ui/svelte`, `packages/blocks/svelte` | `tools/check.sh`: remove the apps/design-svelte step. Parity: templ vs canonical. Screenshot and behaviour tools: site only. |
| **React / Vue / Solid** (not built yet) | both `apps/site` and `apps/design-svelte` once the new app replaces them; templ + Svelte outputs | Add the runtime first ([docs/add-a-runtime.md](docs/add-a-runtime.md)): primitives via codegen, a block emitter, an app. Then switch parity to *new runtime vs canonical* and remove the templ/Svelte steps from `tools/check.sh`. Go is only needed while templ exists. |

In every mode, keep:
- fixtures and contract validation;
- tokens, adapter and the ui8px lint;
- the brand-token guard and the standalone compile;
- link checking;
- the behaviour script and its test.

Update `README.md` (Quickstart, Pipeline), this file and `docs/` in the same change.

## Definition of done

A change is done only when all of these hold:

- [ ] `bun run check` ends with `all checks passed`. That means:
  - no generator drift;
  - contract **0 errors, 0 warnings**;
  - ui parity and blocks parity **0 mismatches**;
  - ui8px **0 violations**;
  - no brand tokens in `packages/`;
  - packages compile standalone;
  - both apps build.
- [ ] For visual changes: you ran `bun run shots` (and `shots:modes` for theme or mobile changes), **opened the images**, and compared them with Figma. Section height deltas in `report.json` must not get worse. Check dark mode and 390px.
- [ ] For behaviour changes (`ui8kit.js`, Sheet, ThemeToggle): `bun run test:behaviors` passes.
- [ ] New utilities are reviewed into `tools/ui8px/allowed.extra.json`: on-grid, token colors, no arbitrary values.
- [ ] Docs updated if a command, path or rule changed: `README.md`, `docs/`, `.manual/`, `.cursor/rules/`. Relative links are checked by `bun run docs:links`, which is part of `check`.
- [ ] `.project/STATUS.md` updated when a deliverable changes state.
- [ ] Committed and pushed. Never push with a failing check.

## What to log in `.project/backlog/`

Create one file per problem, named `<tool>-<issue>.md` (e.g. `fig2design-…`, `ui8px-…`, `codegen-…`, `brand-os-…`, `contract-…`, `templ-…`, `blocks-…`, `site-…`). Each file has a title, **Status** (`open`, `worked-around`, `fixed`, `deviation`, or `decided: … (who, date)`), **Context**, **Impact**, and **Proposed fix**. Add a repro if there is one. Log:

- tool bugs or missing features, together with the workaround used here;
- deliberate deviations from Figma or from a request (e.g. an off-grid value snapped, a breakpoint change);
- anything you could not verify.

The format is described in [.project/backlog/README.md](.project/backlog/README.md). A summary of open items is in [docs/troubleshooting.md](docs/troubleshooting.md).
